Database schema & seeders

Important table: home_page_sections (Home Page admin manager). Use this schema exactly:

CREATE TABLE home_page_sections (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    section_name VARCHAR(255) UNIQUE NOT NULL,
    title TEXT,
    subtitle TEXT,
    description TEXT,
    image VARCHAR(255),
    button_text VARCHAR(100),
    button_url VARCHAR(255),
    `order` INT DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    extra_data JSON,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

Seeders: database/seeders/HomePageSectionSeeder.php — creates hero, banner_1..banner_3, offers. Preserve order and defaults.

Other tables include standard ecommerce: products, categories, orders, order_items, users, addresses, coupons, pages, faqs, images, revisions, settings, etc. Use migrations in database/migrations for exact definitions.

Routes are defined in routes/web.php. Key routes (AI should implement same paths + expected behavior):

PathMethodController@Method / Notes

/admin/*GET/POST/PUT/DELETEAdmin panel routes grouped with auth + role middleware

Contract notes for forms and APIs:

  • Image upload endpoints expect multipart/form-data, validate image types (jpg/png/gif/webp), max 5MB, store under public/assets/images/
  • Admin forms protected with CSRF and role middleware `role:master_admin,admin,staff`
  • Checkout requires authenticated user and uses `nocache` middleware on sensitive routes

Repro steps for an AI or automation tool

  1. Create PHP 8.3 project skeleton and install composer.json dependencies exactly.
  2. Create Node environment and install devDependencies from package.json.
  3. Create models with the same names and migrations matching the DB schema referenced above and migrations folder copy.
  4. Implement controllers with the same public methods and routes as in routes/web.php. Respect middleware and guards.
  5. Implement Blade views with the same file paths; use data contracts (controller -> view variables) similar to original controllers (e.g., $heroSection, $bannerSections, $products).
  6. Implement admin panel with role-based access and image upload handling (5MB limit, stored at public/assets/images/). Ensure old images are removed on replace.
  7. Seed default home page sections using HomePageSectionSeeder and run migrations/seeders to produce baseline demo content.
  8. Build frontend assets with Vite; ensure Blade templates include the built assets (Vite manifest usage or @vite helper).
